# 小小世界 · Pixel Memory World V12

一个可以让很多人同时进入的像素纪念空间。

你可以把它理解成：

> **把生日、纪念日、毕业、告别或一段共同回忆，做成一个大家可以一起走进去的小世界。**

它不是普通的电子贺卡，也不是只有文字和照片的留言页。每个人会先做一个自己的像素小人，再通过同一个 6 位邀请码进入房间。大家可以在同一个空间里走动、聊天、放纪念物、播放音乐、一起庆祝，还可以从房间里的门出去，进入一张“回忆寻宝”地图。

当前版本：**V12**

---

## 第一次来，怎么玩？

如果你只是第一次接触这个项目，不需要先懂代码。

### 房主

1. 打开网页。
2. 点击 **“创建一个世界”**。
3. 选择生日 / 纪念日 / 毕业 / 告别。
4. 填写主角名字、日期和一句邀请语。
5. 选择房间风格与背景音乐。
6. DIY 自己的像素小人。
7. 进入房间后复制顶部的 **6 位邀请码**。
8. 把邀请码或网页链接发给朋友。

### 朋友

1. 打开同一个网页。
2. 点击 **“输入邀请码”**。
3. 输入房主发来的 6 位代码。
4. 做一个自己的像素小人。
5. 推门进入同一个房间。

进入以后可以：

- 电脑用 WASD / 方向键移动；手机网页会显示触控方向键；
- 靠近家具后按 **E** 互动；
- 聊天、抱一下、留言；
- 放照片或纪念物；
- 和大家一起播放音乐；
- 一起按下“庆祝”；
- 从房间右侧的门进入 **Memory Quest / 回忆寻宝**；
- 把真实照片处理成像素线索，藏进地图；
- 给宝藏配一段文字或 15 秒以内的录音；
- 让其他人沿着小路找到它。

## V12 重点做了什么

V12 的重点不是再加功能按钮，而是把原来“像网页里摆了几个像素方块”的感觉，继续往真正的像素世界推进。

这一版包括：

- 室内房间的墙体、地板、光线和家具层次；
- 像素小人的头、头发、身体、手脚与阴影；
- 上 / 下 / 左 / 右四个移动朝向；
- 行走时的腿部动画；
- 手机网页增加触控方向键和 E 互动键；
- Y-sort 深度关系：越靠近屏幕下方的人物越显示在前面；
- 室外树林簇、草丛、石头、树桩、花丛、路牌；
- 河流、木桥、水塘与道路更明确的地形关系；
- 前景树冠遮挡，让人物真的有“走进树林”的感觉；
- 萤火虫、飘叶、水流等轻量环境动态；
- 门外小屋、石阶、围栏、芦苇等地图地标；
- 不再用明显的 SVG 曲线告诉用户路线，而是让地图本身承担探索路线；
- 视觉代码统一到 **world.css** 和 **world.js**，旧的 V11 过渡文件已经移除；
- 场景监听做了减负，避免视觉层因为频繁 DOM 观察产生不必要的性能开销。

> 目前地图仍然是纯前端 DOM/CSS 方案，没有引入 Phaser 或 Tiled。这样可以先保持现有多人联机和房间功能稳定，再决定什么时候进入真正的 Tilemap 游戏架构。

### 为什么一些代码里还会出现 V7 / V8 / V9 / V10？

这是为了兼容以前已经创建过的本地数据。

例如部分 localStorage / IndexedDB key 仍然沿用旧版本名称。它们不代表当前项目版本还是 V7 或 V9，贸然改名反而会让旧房间或旧录音在浏览器里“消失”。

当前产品版本以本 README、页面标题以及 /api/health 返回的版本为准：**V12**。

## 联网到底是怎么工作的？

网页有两种运行方式。

### 1. 真正公网联机

当网页配置了后端地址后，会使用：

- **HTTP / REST**
  - 创建房间
  - 读取房间
  - 保存房间共享内容
  - 上传图片 / 音频
- **WebSocket**
  - 玩家位置
  - 聊天
  - 庆祝状态
  - 房间互动
  - Memory Quest
  - 实时同步

这时，电脑、手机、不同城市的人都可以进入同一个邀请码。

### 2. 没有后端时的本地演示

如果没有配置服务器，网页会回退到浏览器 BroadcastChannel。

它适合自己试玩、同浏览器环境演示和调 UI，但这不等于真正的公网多人联机。

## 最简单的本地运行方式

要求：Node.js 20 或更高版本。

### 第一步：安装服务器依赖

~~~bash
cd server
npm install
~~~

### 第二步：启动

~~~bash
npm start
~~~

默认地址：

~~~text
http://localhost:8787
~~~

直接在浏览器打开这个地址即可。

服务器会同时托管网页，所以不需要再额外启动一个前端开发服务器。

### 两台设备在同一个 Wi-Fi 下测试

假设电脑局域网 IP 是：

~~~text
192.168.1.20
~~~

手机和电脑连同一个 Wi-Fi 后，手机打开：

~~~text
http://192.168.1.20:8787
~~~

然后：

1. 电脑创建房间；
2. 把 6 位邀请码输入手机；
3. 两边移动人物；
4. 测试聊天、纪念物、音乐与寻宝地图。

## GitHub Pages + 公网服务器

GitHub Pages 只能部署静态网页，不能运行 Node WebSocket 服务。

常见线上结构：

~~~text
GitHub Pages
    │
    │ 网页
    ▼
浏览器
    │
    ├── HTTPS REST
    └── WSS
         │
         ▼
Render / Railway / 云服务器
~~~

第一次打开 GitHub Pages 时，可以通过参数告诉网页后端在哪里：

~~~text
https://2550993244-cmd.github.io/pixel-memory-world/?server=https://你的后端域名
~~~

网页会把服务器地址保存到浏览器 localStorage，之后再次访问会继续使用。

如果 Node 服务直接托管整个仓库，则只需要一个域名，这种方式更省事。

详细部署见：**[DEPLOY.md](./DEPLOY.md)**

## 怎么确认真的连上公网？

部署服务器以后，在浏览器打开：

~~~text
https://你的后端域名/api/health
~~~

当前版本正常应看到类似：

~~~json
{
  "ok": true,
  "version": "v12"
}
~~~

进入房间以后，顶部状态也会显示类似：

~~~text
2 人在线 · 公网联机 · 86ms
~~~

推荐用两台不同设备测试：

1. A 移动，B 是否能看到；
2. A 聊天，B 是否出现；
3. A 放纪念物，B 是否立即看到；
4. A 播放音乐，B 是否同步；
5. 两个人一起从门进入回忆地图；
6. A 藏一个宝藏，B 是否能发现；
7. A 放一段录音，B 找到以后是否能播放。

这 7 项都通过，才算“同一个世界”基本打通。

## Memory Quest 是什么？

房间里有一扇通向外面的门。

它不是另一个普通功能页，而是这个项目里很重要的一部分：

> 大家可以把真实经历变成地图里的地点和宝藏。

当前流程：

~~~text
上传照片
   ↓
浏览器提取几个画面区域
   ↓
降低分辨率 + 颜色量化
   ↓
生成像素线索
   ↓
选择其中一个
   ↓
写一句话 / 录一段声音
   ↓
放到地图里的某个位置
   ↓
其他人走过去发现
~~~

当前这套“照片自动像素化”仍然是轻量原型，不是 AI 精确识别人物或建筑。

未来可以继续升级为：

~~~text
照片
 → 主体分割
 → 识别人 / 建筑 / 标志物
 → 像素化重绘
 → 自动生成碰撞区域
 → 拖进 Tiled / Tilemap 地图
~~~

## 当前还不是最终正式产品

这个仓库目前适合：

- Demo；
- 作品展示；
- 同学朋友一起测试；
- 产品原型；
- 继续迭代像素空间。

还不适合直接当成大规模正式线上产品。

主要原因：

- 房间数据仍是轻量持久化方案；
- 上传文件依赖服务器本地目录时，云平台重新部署可能丢失；
- WebSocket 目前偏单实例；
- 没有正式用户账号体系；
- 没有完善的房主权限、举报、删除和内容安全机制；
- 世界地图目前仍然是 DOM/CSS 场景，不是真正 Tilemap。

如果以后要长期运营，推荐升级：

~~~text
房间数据      → PostgreSQL / CloudBase
图片和录音    → R2 / COS / OSS / CloudBase Storage
实时广播      → Redis Pub/Sub / 专门实时服务
身份          → 匿名账号 / 微信 OpenID
地图          → Phaser + Tiled
人物          → 正式 spritesheet
~~~

## 接下来最值得做什么？

### P1 · 真正 Tilemap

把目前的 DOM 百分比地图升级为：

- 16×16 / 32×32 网格；
- Ground / Path / Object / Collision / Foreground 分层；
- Tiled Map Editor 编辑；
- 摄像机跟随；
- 更大的可探索地图。

### P2 · 正式角色 spritesheet

为 DIY 角色生成统一的正面、背面、左右、idle、walk、sit、wave、hug 和 celebrate 动画。

### P3 · 用户真正自己搭世界

让房主可以拖动家具、上传照片生成像素物件、自定义地标、自定义路线，并保存自己的世界布局。

### P4 · 长期保存

让一个生日房间不是“当天用完”，而是几年后还能重新进去。

这会让“小小世界”从一个多人生日网页，逐渐变成：

> **很多人共同留下、并且以后还能重新走进去的记忆空间。**
